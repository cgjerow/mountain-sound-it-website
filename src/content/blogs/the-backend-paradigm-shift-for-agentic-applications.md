This post is in progress.

Backend programming has long centered on a familiar contract: accept a request, validate input, call services, return a response. Agentic applications change that contract. The consumer is often a model that discovers tools, plans multi-step workflows, and synthesizes results—not a front-end that renders a fixed screen.

What shifts for backend engineers? How do authentication, authorization, and observability adapt when the caller is an agent? What does "good API design" mean when the interface is a tool schema instead of a REST resource?
